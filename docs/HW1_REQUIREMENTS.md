# HW1 采集软件要求对照

依据：[第一次大作业：移动感知数据采集 App 开发与步行数据特征分析](http://10.112.165.210:9000/multi_source_fusion/docs/hw1_assignment.html)，2026-10-15 读取。

| 作业要求 | 1.1.1 实现 | 核验方式 |
| --- | --- | --- |
| 枚举并尽量完整采集所有可用传感器 | TYPE_ALL、多实例独立编号，连续/变化/单次触发按模式注册，默认全选 | 真机传感器清单与 manifest |
| 加速度、陀螺仪、线性加速度、重力 100–200 Hz | 默认 200 Hz，可选 100 Hz；磁场 50 Hz，旋转向量 100 Hz，环境慢变量默认周期 | SamplingPolicy 回归；真机 CSV 样本数 ÷ 全程时长 |
| 毫秒时间戳，同时保留单调时钟 | 原始 elapsed realtime ns、relative_s、wall_ms；64 位纳秒在 JSON 中使用字符串 | 存储往返与精度回归 |
| 运动、环境 CSV 交错实时写入 | sensors.csv，缓冲定期刷新；JSONL 保留完整原始向量 | CSV 与 JSONL 对照 |
| Wi-Fi / BLE / 蜂窝单独 network.csv | 30 秒 Wi-Fi 扫描、BLE 每设备最多 1 Hz、蜂窝事件与更新；保留源时刻、去重缓存 | 真机开关/权限/节流/观测验证 |
| 已申请定位时记录 GNSS 经纬度与速度 | 1 秒请求周期，保留速度、精度等可用字段；文件沿用 locations.csv | 室外真机定位；缺失字段空白 |
| 开始/停止、采样状态与实际频率 | 原生前台服务、逐传感器状态、sessionHz，通知栏停止 | 真机前后台与权限拒绝 |
| 停止后导出 | 系统文件选择器导出完整 ZIP | ZIP 完整性回归与界面流程 |
| 携带位置、关键事件、状态段 | 携带位置设置；事件与状态分开；自动生成从 0 秒到停止的 labels.csv | 区间回归、人工核对真实过程 |
| 连续 20 分钟、至少 3 种状态、数据规格 | 进度与数量提示；collection_check.json、data_spec.md | 真机完整通勤试采，核对最大间隔与全程波形 |

`collection_check.json` 只核对采集侧指标。正常停止或平均频率足够不能证明过程没有缺口，因此始终提示人工核对连续性。FFT、步频、分类器和完整课程 self_test 属于后续分析，不会由采集 App 伪报通过。

新采集会话的 `labels.csv` 无表头，格式为 `start_s,end_s,state`，区间左闭右开。状态切换结束上一段；关键事件只写 markers.csv / samples.jsonl，不改变状态。默认初始状态为静止，采集前应按实际情况设置。导出后可用文本或分析脚本修订漏标；旧会话仍可回看导出，不会自动补造新通道数据。

## 真机验收

1. 安装 outputs/MultiSense-debug.apk。保持默认全选与 200 Hz，设置携带位置和初始状态，允许精确定位、附近设备与电话权限，打开系统定位、Wi-Fi 扫描及蓝牙。
2. 先采 40 秒，期间依次切换三种真实状态，并添加“进入楼宇”事件。确认事件不改变当前状态，停止后检查 labels.csv 首尾、关键事件和 network.csv。
3. 再进行一次至少 20 分钟的真实通勤，包含 ≥3 种真实运动状态，记录 2–3 个关键事件；覆盖切后台与息屏。不要中途停止后拼接。
4. 导出 ZIP，检查四个核心运动通道的全程实测频率、最大间隔、时间戳异常和全程波形。若低于 100 Hz，保留事实，调整设备采样/电池策略并重新试采。
5. 分别拒绝精确定位/附近设备/电话权限、关闭 Wi-Fi/蓝牙/定位，确认对应数据源给出不可用原因，其余传感器可继续保存。拒绝电话权限时应提示仅进行定时基站更新；允许电话权限后重新采集，检查蜂窝变化监听。检查扫描节流或无周边设备时没有伪造观测。
6. 核对规格说明与标签，原始数据本地留存。提交成员数据说明和标签，原始大文件不纳入版本库。

构建、Java 存储测试和浏览器模拟验证不能替代以上真机验收。

Android 参考：[Wi-Fi 扫描与权限/节流](https://developer.android.com/develop/connectivity/wifi/wifi-scan)、[蓝牙权限](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)。
